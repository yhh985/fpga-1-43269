A cancel that arrives while the clips are being saved removes the clips the run made, including an Edit source recording it saved (one an earlier run kept, or one another Edit now plays, stays; an Edit's source handoff and this cleanup share a lock), and still answers 499. A second run under a `cancel_id` that a running audio run holds gets 409, so one cancel never stops two runs. A cancel that arrives before the run starts is kept for 30 s.\n- New `POST /audio/analyze` measures an upload, history clip or saved voice: duration, integrated loudness (BS.1770-4, gated), true peak (4x oversampled), clipped samples (runs of 3+ identical samples at full scale that the waveform lands on or leaves more steeply than a smooth peak could: PCM rounds a clean peak to a flat top of L samples that it leaves by at most about ((L + 1) / (L - 1))² quantization steps, so the limit is twice that, using the WAV's own sample width (for 32-bit PCM the float32 spacing near full scale, 2^-24). Clean 16-bit tones from 1 Hz to 2 kHz at 0.99-1.0 of full scale count 0 (400 random tones), and a 2% overdrive counts from 10 Hz to 1 kHz, in 8-bit too, where a clean tone within 1% of full scale also reads as clipped because 8-bit is too coarse to tell the two apart) and the span that holds sound (a final partial 20 ms frame counts, so a 6 ms beep has a span). With `expected_text` it transcribes with the resident speech-to-text model (or the default) and returns `match_score`, 1 minus the word error rate, or null when the two texts are too long to align (over 50 million word pairs, about a quarter second of numpy work). Nothing is saved. Clips over 10 minutes get 413.
