# 读图、切图、语音与切歌加速版

本页记录上一轮加速修改。用户确认速度已有改善，随后反馈音效噪声和静音误触发。后续修复及当前测试数据见 [语音误触发与音效噪声修复](语音误触发与音效噪声修复.md)，本页单次推理、旧链路和识别率数字保留为历史依据。

本次针对实板反馈修改，最终工程位于 `E:\anlo_project\liantiao`。修改前源码和原发布码流保存在 `verification/before_live_fix_20261020_180347`。完整旧版备份为同级 `liantiao_备份_漫画开发前_20261020_132403`。两块板必须一起更新根目录 `deliverable` 中的配套码流。

## 改动及验证边界

1. **下一张预读**：当前画面和转场释放帧缓冲后，利用另一块已有帧缓冲提前读取下一张。收到手动/语音/自动下一张命令，若预读就绪、图片编号和缩放倍率一致，直接提交显示，不再读SD卡。预读期间收到语音请求会保留。没有新增帧存储。上一张、首张、改变缩放倍率，以及尚未读完的下一张仍要等待读卡；连续快速翻页不能保证每次命中缓存。
2. **转场**：每视频帧进度步长2改为4，60Hz下覆盖及展开合计约0.33秒，不含尚未完成的读卡等待。保留源读取、SDRAM写完、读者确认与转场占用保护，预读失败保留原画面并停止后台重试。
3. **语音句末**：旧前端会把高于固定门限的底噪也转为有效特征，导致系统一直等不到六个安静帧。新增约256ms底噪校准与自适应门控；仍保留原模型及六个32ms安静帧，合成能量回归中说完后不超过224ms进入推理。MAC计算约1.5ms，冷却从1.5秒减至0.4秒。这不是实板端到端响应时间测量。
4. **切歌**：此前改变曲目后固定等16个时钟便重启。若文件系统此时还在处理图片/FAT事务，可能重读旧曲。现在等文件系统确认实际曲目，再清理并重新缓冲。并发BMP读操作回归校验900个PCM采样；移除确认条件的旧逻辑负对照会失败。
5. **音效诊断**：返回数据约100ms无活动则回退HX本地原声，避免断线后一直静音。屏幕 `FX WAIT` 表示请求了音效但没有返回活动；`FX RETURN` 表示有返回数据跳变。此提示不能验证音效或接线质量。串行仿真通过衰减/低通/失真及六组相位与延迟检查，尚未复现实板静音的具体原因。

生产自适应前端重新回放280段原留出合成录音：命令74/80，错误方向2次，非命令误触发1/200；固定种子、PCM16幅度±250均匀背景噪声下为71/80、错误方向4次、误触发3/200。没有真人独立录音，不能据此保证现场识别率。

## 先测图片速度

1. 将 `card_fast_test` 的3张 `PIC001.BMP`～`PIC003.BMP` 放到FAT32卡根目录。测试时根目录只保留这三张BMP；原图在电脑备份。三张均为640×480、24bit无压缩、每张921654字节，颜色与编号不同，便于确认真的换图。目录项顺序决定扫描顺序。
2. 烧录新的两块码流，确认图片正常显示，先等待几秒让下一张预读完。手动翻下一张，比较是否直接转场；随后连续快按，观察缓存未就绪时仍需读卡。再确认上一张和缩放没有花屏或错误图片。
3. ACA按 **S4（T4）** 进入语音，确认屏幕 `VOICE READY`、D6常亮，初次进入先安静约2秒。正常说“下一张”，说完停顿；观察屏幕 `NEXT` 与画面变化分别发生的时刻。`NEXT`迟才出现，排查语音；`NEXT`立即出现但画面迟，排查图片加载和转场。用手机同时拍到屏幕与声音可记录端到端耗时。
4. 不把“等待预读几秒”当作缓存命中证明。目前没有预读就绪的屏幕指示；若仍很慢，请分别记录小图首次下一张、后续间隔几秒下一张、上一张、以及语音 `NEXT` 出现时间。

大分辨率原图即使最终显示640×480，板上仍需读取更多SD字节。可在电脑运行：

```powershell
& "$env:USERPROFILE/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe" tools/prepare_fast_images.py "E:/原始图片" "E:/快速图片"
```

脚本只创建新的640×480等比例留黑边RGB24 BMP，不修改原图，不覆盖已有输出；当前工程最多32张。复制生成BMP到卡根目录，避免原大图一起参与扫描。此转换会降低大图放大后的细节，需保留高分辨率原图。

## 再测音乐和音效

1. ACA **S4退出语音**，HX在图片操作页用K2进入音乐模式。卡根目录放 `card_test` 的3首WAV，分别是220/660/1320Hz测试音。
2. ACA **S2（H14）下一首，S3（P6）短按上一首**。听音高是否明显不同；按一下等待新曲重新缓冲，不以同一首歌曲的相似开头判断失败。
3. 长按ACA **S3约1秒**切音效。半幅衰减应变小声；低通对低频测试音变化可能不明显，可用宽频音乐；限幅失真需足够输入幅度。
4. 若为 `FX WAIT` 且仍听到原声，这是保护回退，**不代表音效成功**。核对四根数字音频线，见 [音乐接线](../MUSIC_上板测试.md)。若 `FX RETURN` 但声音异常，记录具体档位、是否两声道都有问题和屏幕状态，继续定位返回采样。
