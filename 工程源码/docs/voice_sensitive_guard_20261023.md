## 实际恢复与限制

恢复 20261020 早期 dense 模型及原生 48 帧窗口，SHIFT=9，原分差门限 109。
权重 SHA256 `431bce25f395111c1d06896726ce561e85a1faba4fffa74ab542583ad38f71dc`，
与 `E:/anlo_project/liantiao/verification/before_noise_fix_20261020/deliverable/release_manifest.json` 核对一致。

每句话只识别一次，不再要求三次缩放结果都通过，也不再先要求六/八帧安静资格。
保留原来至少六帧有效声音、六帧静音结束、总长至多 64 帧和 400ms 指令冷却。
原生窗口不会压缩长口令，过慢说话可能超出窗口；这也是本次回归旧方案的取舍。

新增/保留的防误触发措施：

1. 沿用最新校准背景估计与双门限 VAD，短脉冲、单频带干扰不直接等于口令。
2. 抹掉当前语句开始前的旧特征，避免上句话残留又被噪声触发。
3. 指令分差仍需达到原来的 109，并要求该指令原始 logit >=0；
   三类都很差时，不仅因为其中一个相对没那么差就翻页。
   这是针对固定旧模型经验证选择的附加门限，不是概率，不能跨模型通用。

引擎增加 `NORMALIZE_UTTERANCE`、`MAX_UTTERANCE_FRAMES`、`MIN_WINNER_SCORE` 参数。
保留新模型路径作为可回退配置，但本版顶层明确使用旧模型、原生窗口、单次推理。

## 验证结果与未解决问题

用合成验证集选择策略：正确数损失不超过命令试验数 1%，不增加反方向，
非口令误接收至少减少20%。随后固定参数运行独立合成测试，不据其结果继续调参。
真人两句旧录音用于开发诊断，没有独立真人验收。

| 完整合成流指标 | 原早期版 | 本对照版 |
| --- | ---: | ---: |
| 验证正确 /696 | 382 | 380 |
| 验证反方向 | 76 | 54 |
| 验证非口令误接收 /1740 | 62 | 48 |
| 独立测试正确 /696 | 380 | 367 |
| 独立测试反方向 | 53 | 37 |
| 独立测试非口令误接收 /1740 | 74 | 54 |

非口令包括其他合成人声及带噪变体，不只是电气杂音。
大量变体来自相同合成声音，不是独立真人数量，也不是每分钟误触发率。
另做120秒纯合成非语音压力测试，14个候选，零翻页指令。

**本版不是“噪声都不会通过”：独立测试仍有54次非口令误接收、37次错方向。**
旧真人录音两句经原始早期逻辑为上一张、拒识；本版仍为上一张、拒识。
没有把这句“下一张”修好，没有证明现场成功率提高，不能宣称解决板子拒识。
相比最近 continuity 版的同类合成测试（正确400、错方向1、误接收8），
本旧模型分支的这些指标更差。交付它是为了按用户要求提供旧版轻门槛对照，不是替代已验证结论。

实际 native RTL 逐项验证原生窗口、首样本、长短边界、128帧回绕、旧历史屏蔽及决策；
开发真人例子两次 logits 与整数参考一致，第二句保持显式失败。
单次推理仿真约1.483ms，另有六帧192ms静音端点；这不是说完到新图可见的板上时延保证。
串口、PCM、双板UART确认、丢ACK重试/去重、音效与切图预取回归通过。

## 使用

ACA 使用 `aca420_voice_sensitive_guard.bit`。
HX 与 continuity/gate_fix/PCM跟踪版相同；已用这些HX版本的不需重刷，
否则可使用配套 `hx4s20_voice_sensitive_guard.bit`。
短按 ACA S4，等 VOICE READY 后说完整口令。
用户目前无法操作板子，本次没有要求立即刷写或再次录音。

串口保持460800 baud、0x55、596字节。单次推理只写第一组三类分数，另两组为零。
离线工具必须明确使用单次/原生模式，不能把后两组零当成两票背景：

```powershell
python tools/decode_voice_pcm.py verification/<capture>.bin --passes 1
python tools/replay_voice_capture.py verification/<capture>.feature.bin --recognizer sensitive
```

恢复上一版可直接使用已封存的 `E:/anlo_project/liantiao/deliverable/voice_continuity_20261023`。
修改前引擎和顶层保存在 `archive/before_sensitive_guard_20261023`。
