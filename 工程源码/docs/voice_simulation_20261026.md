# 语音识别修正与回放仿真

本次代码、数据和结果均在 `E:/anlo_project/liantiao/development/audio_crc` 内。未改动板上 RTL，也未发布码流。

## 本次实现

新文件 `voice/tools/train_masked_acoustic_codes.py` 独立保存修正模型，保留之前实验以便对照：

- 每层卷积前后屏蔽真正的无效补齐区域，归一化统计也只使用有效时刻。
- 真实静音与补齐区分开处理；两端保留 14 帧真实静音上下文，避免声音靠近片段边界时改变判别。
- 保留完整句子 CTC 训练、随机语音起点、静音空文字目标和合成噪声增强。
- 使用合成验证集选择检查点和接受条件；已有两句真人录音不参与训练或参数选择。
- 开始训练时保存源码快照与输入文件哈希，结束时检查文件是否改变。

## 仿真范围

`voice/tools/simulate_masked_acoustic_codes.py` 从既有 48kHz PCM 录音出发，经现有整数降采样、频谱、特征与语音切分，再进入新浮点模型。包括原录音、四分之一音量、20／10／6dB 加性白噪声、前导静音、特征序列速度变化，以及共 40 秒静音／白噪声／嗡声／脉冲负例。

特征序列速度变化只检验模型对时长的容忍，不等同于重新录制不同语速的真人音频。模拟噪声也不等同于真实接线电气干扰。真实录音仅两句且反复用于开发诊断，不能据此声称真人识别率。

结构一致性检查同时覆盖：单独与合批、前导静音平移、任意无效补齐值，以及训练阶段的补齐宽度。通过这些检查只证明补齐处理一致，不等于口令识别成功。

`voice/tools/evaluate_masked_ctc_paths.py` 另比较完整 CTC 对齐概率：12 个已知短语和空白共同竞争，同时要求相对差值和绝对似然条件。它不是强行在两条指令之间二选一，条件仅由合成验证集选择。

## 结果文件

本轮 100 个训练轮次已完成，验证集选中第 44 轮；来源文件与缓存的结束哈希检查通过。结果为**部分成功，未达到部署条件**。

| 检查 | 结果 |
| --- | --- |
| 补齐区改值、训练补齐宽度变化 | 有效输出最大差为 0 |
| 前导静音平移 | 有效输出最大差为 0；真人回放文字和接受结果一致 |
| 单独／合批 | 最大浮点差 0.00002289；真人指令与文字一致 |
| 原录音“上一张” | 文字正确，但差值 0.5483，低于验证集选定的门槛 1，拒识 |
| 原录音“下一张” | 文字正确，差值 3.7085，接受 |
| 四分之一音量 | “上一张”接受，“下一张”文字正确但拒识 |
| 20dB／10dB 白噪声 | “下一张”接受；“上一张”分别解码为“上一首”／“上一点”，拒识 |
| 6dB 白噪声 | 两句文字正确，但均拒识 |
| 特征序列加快至 1.3 倍 | “上一张”接受；“下一张”被误认成“上一张”并接受，这是明确失败项 |
| 40 秒负例音频 | 无指令；各负例均被语音切分阶段拦住，没有产生候选，因此不能据此证明分类器对所有噪声都能拒绝 |

结构测试的浮点绝对容差为 0.0001，允许 CPU float32 卷积因批次大小改变累加顺序造成的舍入差。初始未训练网络用 0.00002 检查能通过，训练后 logits 增大，单独／合批差 0.00002289 超出原容差；因此明确改成 0.0001 并记录实际误差，而非声称逐位完全一致。其他补齐相关差仍为零。

合成完整流测试（696 个口令试验、1740 个非口令试验）：逐帧拼字接受正确 410、方向错误 15、非口令误触发 6；完整 CTC 序列评分正确 468、方向错误 15、非口令误触发 9。它改善了部分漏识，但没有解决方向错误。两条真人回放在完整序列评分下也是“下一张”接受，“上一张”因与其他短语的差距不足而拒识。两种解码器的门槛分别由验证集选择，没有根据这两句真人录音降低门槛。

原录音能够解码为正确文字是进展，但音量／噪声／速度敏感和方向误识仍未通过。不能把补齐修复成功、静音无文字、原录音一条指令接受，包装成语音控制已经完成。
