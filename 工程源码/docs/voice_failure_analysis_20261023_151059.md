# 本轮“下一张”拒识分析

数据：`verification/voice_capture_20261023_151059.bin`。用户在三次“下一张”的采集提示后回复“说完了”。这只确认批次，不把所有噪声候选标成命令。

## 当前可证实的事实

- 30 秒共 938 个有效包，电脑抓取链路 CRC 错误 0、无序号缺口、无上报溢出。这不能证明 ACA-HX 的另一条 UART 没有错误。
- 对 7 个完整且进入模型的候选重放，全部分类分数与 FPGA 整数计算相同。暂未发现推理算术错误。
- 有 16 个完整候选被判为有效语音过短，6 个完整候选包含背景类拒识，3 个包含低分差，2 个包含多次判定不一致。这些原因可重叠；候选不是说话次数。
- 编号 15：6.624 秒开始，7.584 秒端点完成。三次均判下一张，分差 1585/1861/1951，超过门限 791；拒识标志为 0。不能说本轮模型一次也没认出。
- 编号 13：1.344 秒开始，长度 75 帧，被前置安静资格拦截；额外离线运行仍全部判为背景。因此只放宽安静资格不能救回此候选。
- 84 个上报包的 byte5 bit4 为 1，表示原始 PCM 曾出现 0x7fff/0x8000 的 100ms 保持监测标记；不是 84 个削顶样本，也不能据此断言一定是模拟过载。编号 15 的区间也有此标记，故满幅不是所有失败的充分解释。

## 代码与证据指向的问题

1. 当前模型 config 明确 synthetic_only，真实麦克风输入与合成训练分布可能不匹配。多数候选三次都偏向背景，单纯调低 margin 不能把背景类变为下一张。
2. 当前 VAD 将非语音特征直接置零，部分候选存在多个零帧间隙。只有处理后特征，不能分辨真实停顿、噪声或误删语音，也无法重建原始声音。
3. 输入存在满幅监测。ES8388 初始化已设 PGA 0dB，且注释为外接 MAX4466 前置放大；不能假定还有很大的 codec 增益可降低。需要核实外接增益/幅度与 I2S 采样是否正常。数字端事后缩小饱和样本不能恢复失真。
4. NEXT 是 ACA 收到 HX 确认后的状态，再经周期状态包送回 HX 显示，并在一秒后或新语音开始时清除。当前电脑串口包没有 event_valid、ACK、last_command 或 HX 图片提交状态。即使编号 15 分类通过，也不能仅凭这份包确认每一步是否成功。

## 解决顺序与验收

1. 补齐按同一命令序号关联的识别通过、发送、HX 接收确认、提示显示、图片提交记录，避免把拒识、确认失败和 SD 读图等待混为一谈。板间 ACK 不等于图片显示完成。
2. 保留识别前原始 PCM 及频带能量，检查满幅比例、直流、背景和频谱；定位模拟输入过载还是数字采样干扰。现有归一化特征不支持可靠区分这些原因。
3. 在原始输入上评估带噪声估计/迟滞的 VAD，保留短前导缓冲，防止切掉词头；独立检查持续噪声导致的端点拖延。改变前端后需要重训练及独立验证。
4. 用逐段确认的真实上一张、下一张及背景做适配，两类命令分别保留独立采集批次验证；保留其他人声、接线干扰和非口令作为负例。不把整批噪声候选当作下一张训练。
5. 分别测两类召回、方向混淆、背景每分钟误触发，以及说完到识别、识别到 ACK、ACK 到新图显示的延迟。两秒目标应指说完到新图可见的实际板上时间，不能用 4.5ms 推理仿真替代。

本轮只分析并保存证据，未修改识别权重、门限或位流。
