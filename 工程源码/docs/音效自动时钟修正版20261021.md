# 音效自动时钟修正版

## 用户实测与版本对应

本聊天记录中，用户在收到 2026-10-20 晚 `aca420_music_voice.bit` / `hx4s20_music_voice.bit` 后反馈：切音效能够听到音乐旋律，但夹杂大量噪声，未感知明确音效。
对应完整基线为 `E:/anlo_project/liantiao/archive/20261021_pre_crc_baseline`，其中两份码流文件时间分别为 2026-10-20 22:56、23:03。聊天未包含烧录文件的实物哈希，故这是交付与反馈顺序的对应，不能声称已核实用户当时实际加载的位流。

旧版返回链路无逐样本 CRC 校验，只检测 DATA 活动后切入音效，因此音乐夹杂噪声不能作为链路有效的证明。当前诊断版上板报告 `FX CLK LOW`，只证明比例监测检测到异常，不单独证明接线、代码、端口损伤或信号质量中的哪一种是原因。

旧、新顶层都显式设置 32 位/声道。模块默认值 64 不代表实际配置。旧、新引脚约束相同。

## 本次实际修改

ACA 同时测量两种输入时钟排列，连续八次同类位数后发布测量。只有测量有效且正常方向比例不足 4、反向约为 32 时，才在 FPGA 内交换两根输入的用途；正常方向恢复有效 32 位时，自动恢复原排列。空闲时清除测量有效标志，防止把未测量的 code=0 当成 32 位时钟。

这两根管脚始终为输入，不改变外部管脚方向，不动 DATA 与返回数据管脚。内部切换时清除接收/DSP/回声状态，随后必须重新收到通过 CRC 的音频才可输出。CRC 多项式、音频数据格式、音效运算和校验门槛保持原实现。

正常接线/信号不会触发交换。此功能能恢复时钟次序反向的输入，不能修复缺失时钟、坏接触或硬件端口故障，也尚未证明此次实板故障属于可恢复情况。

HX 在音乐模式命令文字位置显示 `SWAP` 时，表示 ACA 已启用内部时钟交换。语音模式仍显示 NEXT/PREV，不借用语音判断位。效果名称仍显示 FX ECHO / FX LOWPASS / FX TREMOLO。显示效果名称意味着 CRC 返回有效，还需实际听音验收。

## 上板复测

保持目前接线，配套更新本目录两份 `*_autoclock.bit`。进入 MUSIC 播放有声 WAV，长按 ACA S3 约一秒切换音效，等一秒看提示。

- `FX ECHO` / `FX LOWPASS` / `FX TREMOLO`：校验返回有效，听是否有对应变化。`SWAP` 表示自动恢复起效。
- 仍为 `FX CLK LOW`：两种输入排列都未得到可选的有效 32 位比例，本次恢复条件未满足，不能称已修好。
- `FX IN CRC`：时钟排列选择后数据仍无有效完整立体声，继续定位数据/采样问题。
- `FX NO RET` / `FX OUT CRC`：去程已有效，返回方向仍需定位。

原声走 HX 本地链路，原声有声不等同于双板音频往返有效。此版不会把错误帧重新放出来制造“有声音”的假象。
