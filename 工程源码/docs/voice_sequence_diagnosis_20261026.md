# 上一张／下一张识别差：实测诊断与开源对照

日期：2026-10-26。工作目录为 liantiao/development/audio_crc。本次未改动板上 RTL、权重 ROM 或发布新码流。

## 必须分清的两个识别器

当前工程的板上实现仍是原有小型分类器；新做的逐字 CTC 模型只是离线实验。下面发现的“静音输出上”是逐字实验的问题，不能倒推成板上旧分类器也会输出这个字。板上 HEAR 仅证明检测到了语音候选，AGAIN 表示候选未通过分类与接受条件，并不等于麦克风没收到声音。

## 已证实的问题

1. **逐字实验学到了起点捷径。** `previous_failure_diagnosis.json` 中，15、40、80 帧全零静音都会在第 0 帧输出“上”，差值约 0.17156。两句真实录音也在特征均值为 0 的第 0 帧先输出“上”，然后输出“一张”。问题不是完全没有声音信息，而是方向字不可靠。原接受差值为 2，这个首字必然通不过；直接降低门槛又会把“下一张”认成“上一张”。
2. **片段标签存在不可靠对应。** 旧训练按语音切分片段，再用覆盖率或最长片段推断是否附整句文字，没有音素级强制对齐。这可能让不完整片段背整句标签，也可能把有效片段教成 other。这是训练风险，不是已经证明的唯一原因。
3. **压幅较重，但没有完全丢失变化。** 真实录音末层约 49% 激活为零、40% 达到上限 4，其余仍有变化。不能把失败描述为整个网络变成常数。
4. **合成语音与真人泛化仍弱。** 旧逐字模型在验证集 667 个口令候选中，未加接受差值前有 364 个文字完全正确；加上选定条件后，完整流 696 次口令只接受对 8 次。既有模型问题，也有接受条件把低置信正确结果挡掉的问题，不能只调一个门槛解决。

## 本次已经做的修正实验

- 完整已知语句训练，保留门控前的频谱，不再猜切碎片段的全文标签。
- 三层时序卷积、逐字 CTC 和辅助短语分类；让“上／下”和后续“一张”按时间关系共同判断。
- V3 额外随机前后静音长度，加入空文字目标的纯静音／近静音训练，专门抑制起点捷径。
- 参数与检查点用合成验证集选择；两句真人录音仅复用诊断。旧测试集曾被其他实验查看，不能称为全新盲测。

V2 合成完整流测试：696 次口令中正确 457、方向错误 21；1740 个非口令试验误触发 4。真人复用回放：“上一张”仅输出“上一”，拒识；“下一张”输出完整文字并接受。有改善，仍不能发布。V3 及静音／平移检查见对应报告与 `verification/acoustic_codes_audit.json`。

最终 V3 测试：696 次口令中正确 446、方向错误 13；1740 个非口令试验误触发 9。两个修正版对本次 6 个静音／近静音样例均不输出文字，但真人识别仍不稳定，不能把消除纯静音输出等同于解决识别。

**额外发现：新卷积实验的补零边界会影响结果。** 同一“上一张”V2 与另一句合批时输出“上一”，单独识别输出“上一首”；V3 合批输出“上一张”，单独却输出“上一首”。多层非因果卷积在补齐区产生非零激活，后续卷积又能读回有效区；当前 forward 没有逐层屏蔽无效时刻。前导静音 0／3／6／12 帧的检查也有文字变化。已有报告因而只能视为指定批处理条件下的诊断结果，不能当作部署准确率。后续训练必须统一真实静音与批处理补齐的语义、逐层屏蔽或采用严格定义状态的因果网络，并用同一句单独／合批一致性检查阻止回归。这是本次新实验的问题，不是已部署 RTL 的直接证据。

## 联网找到的可借鉴方法

- [WeKws](https://github.com/wenet-e2e/wekws)：可训练关键词识别系统。
- [特征与增强实现](https://github.com/wenet-e2e/wekws/blob/main/wekws/dataset/processor.py)：滤波器组特征、语速扰动、时间和频率遮挡。默认特征窗 25ms、步长 10ms；不代表这些数字可以直接替换现有 FPGA 参数而免于重训。
- [流式 CTC 识别实现](https://github.com/wenet-e2e/wekws/blob/main/wekws/bin/stream_kws_ctc.py)：前缀束搜索、空白符与重复字处理、持续时间限制、触发间隔。比只拿每帧最大值拼字更能保留多条候选路径，但不能修复错误训练出来的声学分数。
- [Sherpa-onnx 关键词识别](https://k2-fsa.github.io/sherpa/onnx/kws/index.html)：现有公开中文模型在两句旧真人录音及模拟 8kHz 降采样回放中均识别对。它是电脑上的参考模型，3.3M 参数不能原样塞入当前 FPGA，也不证明所有板上实时输入都完好。

下载的源码保存在 `research/acoustic_codes_20261026/`。静音空目标和随机起点是针对本工程实测问题设计的修正，不声称是上游项目原样采用的方案。

## 下一步的技术判断

先要求小模型通过静音无字符、改变前导静音不改变文字、上／下方向可分的离线检查；再比较前缀束搜索与其他短语竞争评分。必须包含空白和非口令，不能在两条命令间强行二选一。若仍泛化不足，应借助成熟模型做对齐或教师指导，再做量化与资源适配。

当前新模型使用未来 14 帧上下文，约 448ms，只是离线网络的上下文需求；尚未测量 FPGA 总延时，不能声称已经达到 2 秒。模型通过后还需要定点一致性、资源、时序和上板检查。
