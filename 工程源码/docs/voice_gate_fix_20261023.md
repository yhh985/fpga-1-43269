# 识别逻辑与门限修正

本版基于当前 `voice_pcm_trace_20261023` 最新工程修改识别引擎，未再修改特征提取、权重或 HX RTL。工程目录 `E:/anlo_project/liantiao/development/audio_crc`。

## 实际修改

1. 一句话使用六帧静音（192ms）结束，但原先下一句话需八帧静音（256ms）才能得到前置资格。结束与重新允许开始之间存在64ms区间，落在其中的候选会被前置规则拒绝。本版统一为六帧。原规则用作负对照，在同一测试中复现“192ms端点后无法重新接受下一句”；新规则通过。
2. 保留原来三次同方向、各分差>=791的接受路径。增加一条有限放宽路径：三次仍必须全部同一非背景方向；每次分差>=650，且总分差>=3600。背景类和相反方向继续否决。这样允许整体证据强但某一视图稍弱的候选通过，不采用两票即可通过。
3. 接受时清除仅由旧单次门限引起的低分差拒识标记，避免已经发出命令却仍报告低分差拒绝。冷却期间仍明确报告冷却拒绝。

本版确实修改了识别判定，不只是显示或采集。

## 为什么没有直接把791改成很低

同一合成验证候选集：三次各>=791时，正确375、反方向13、背景误触发8。直接降至600变成正确396、反方向14、背景误触发14。两票>=791时，正确426、反方向20、背景误触发18。这些是不同噪声/语速候选，不是人的实测识别率。

新策略仅用验证集选定；人工串口候选未用于选择参数或冒充标签。固定后再检查独立测试集，未用测试集改参数。

| 完整合成流指标 | 旧策略 | 新策略 |
| --- | ---: | ---: |
| 验证命令正确 / 696 | 375 | 383 |
| 验证反方向 | 13 | 13 |
| 验证背景误触发 / 1740 | 8 | 8 |
| 独立测试命令正确 / 696 | 345 | 352 |
| 独立测试反方向 | 1 | 1 |
| 独立测试背景误触发 / 1740 | 4 | 6 |

改善有限，独立测试误触发增加2例；不是完全解决。测试背景比例不是每分钟误触发率。两组均包含同一来源的多个语速、噪声变体，不能将数量当作互相独立的说话人数。

## 仍存在的限制

已抓取的20261023人工候选中，单独换成新的分差规则没有额外救回通过前置门限的命令。编号668三次分差622/1083/671仍低于新策略要求。大量候选的第一名本来就是背景，修改门限不能自动把它们变成正确命令。

旧的20261021录音重放时，新的前置规则让第二个候选进入模型，但模型仍拒绝；结果为上一张、拒识，不能宣称两条口令都已修好。保留这一失败作为回归证据。
