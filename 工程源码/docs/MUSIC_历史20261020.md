# 多首音乐与 ACA 音效上板测试

最终工程位置：`E:\anlo_project\liantiao`。在 TD 中分别打开 `aca420/aca420_audio.al` 和 `hx4s20/contest_proj.al`。两块板都要下载本版对应码流，源代码、模型、约束、仿真工具及验证脚本均放在本目录。

## 功能与操作

1. SD 卡使用 FAT32，音乐直接放在根目录。支持最多 8 个非删除、非目录的 WAV 条目，按 FAT 目录项顺序播放，文件名排序不决定顺序。第 9 首起不加入列表。支持分散簇；单文件 44 字节至 64 MiB。
2. WAV 必须是 PCM1、16 bit、48 kHz，单声道或双声道。MP3、压缩 WAV 和 44.1 kHz 不支持。单声道复制到左右声道。无效格式会静音并显示音乐错误，按下一首可恢复，不自动跳过坏文件。
3. HX 保留原操作：在图片操作页短按 K2，手动→自动→音乐循环；长按 K4 暂停/恢复。进入音乐模式后播放当前选曲，曲尾循环当前曲目。
4. ACA S2（H14 / key_slot_n）短按：下一首；ACA S3（P6 / key_learn_n）短按：上一首。首尾循环。在非语音模式下有效；可提前选曲，进入音乐模式再播放。
5. ACA S3 长按约 1 秒，循环 **原声→半幅衰减→低通→限幅失真→原声**。原声经 HX 本地送 HDMI；其余三档从 ACA 返回 HDMI，必须完成下表新增接线。该按键松开时不会额外触发上一首。
6. ACA S4（T4）切换语音模式。进入后 HX 停止音乐并许可识别；退出恢复音乐。麦克风采样始终不送音箱或耳机。
7. 离开音乐模式再进入会从当前曲目开头播放；切歌清空旧曲缓存，等待当前 SD 事务结束后从新曲开头重新缓冲。暂不提供自动连播下一首、歌名显示、倍速或保调变速。

## 接线

现有 UART 和共地保持：ACA P4-1/E15→HX J2-1/FPGA P4；HX J2-2/N4→ACA P4-2/F13；ACA P4-12→HX J2-12。

增加四根 **3.3V 数字音频线**，不是接模拟耳机插孔。HX 是音乐时钟主机，无须额外 MCLK：

| 信号 | 方向 | HX 接头 / FPGA 管脚 | ACA 接头 / FPGA 管脚 |
|---|---|---|---|
| 音乐 BCLK | HX→ACA | J1-1 / D14 | P4-3 / F14 |
| 音乐 LRCK | HX→ACA | J1-2 / G11 | P4-4 / D16 |
| 原音乐数据 | HX→ACA | J1-3 / G12 | P4-5 / D14 |
| 处理后数据 | ACA→HX | J1-4 / F13 | P4-6 / E13 |

两板分别供电，只共地，不互接供电针。ACA P4-11 是 5V、29 是 3.3V，12/30 是 GND。建议短线并让时钟旁有地线；先以原声确认 SD 与 HDMI，再切换音效。返回数据超过约100ms没有活动时，自动用HX本地原声继续播放，屏幕显示 FX WAIT；检测到返回数据活动显示 FX RETURN。后者仅表示有数据跳变，不能保证音效正确。

引脚依据：ACA 官方 `ACA420-EDA.pdf` 第7页 P4、官方 `安路EG4S20管脚分配表.xlsx` GPIO[0..5]；HX 官方 `4_GPIO.pdf` 第1页及 `2_FPGA.pdf`。HX GPIO 经板载 47Ω 电阻网络重新排列，不能直接把 FPGA 的 GPIOA0 当成 J1-1；约束已经按接头实际映射填写。核对渲染页放在 `verification/*gpio_verified.png`。

## 音效链路

HX SD→WAV 解析→异步 FIFO→32 bit/声道串行音频→ACA 50 MHz 过采样接收、16 bit 效果计算→同步返回→HX 接收→HDMI。约一帧处理延迟。实际 Fs 约 48027.66 Hz，BCLK 约 3.0738 MHz，由现有 PLL 决定。ACA 音乐与自身 ES8388 麦克风时钟独立。最新噪声修复与验收步骤见 [修复说明](docs/语音误触发与音效噪声修复.md)；屏幕 `TRACK 1/3` 表示当前第1首、共扫描到3个WAV记录。

衰减是算术右移一位；低通是每声道独立的一阶 `y=x/2+y_old/2`；失真是四倍增益加有符号饱和，不会溢出反号。模式切换会清滤波状态，可能产生短暂点击声，未实现淡入淡出。UART 失联会回到 HX 原声；返回数据活动由约100ms看门狗监测，无活动时回退原声；路由仅在立体声帧边界切换。

## 验证与复现

在此文件夹运行 `./run_all.ps1 -Build` 完成通用、ACA、HX 顶层、音乐专项仿真和两板完整实现。音乐专项独立运行 `./sim/run_music_tests.ps1`；语音整数逐项对照运行 `./voice/run_voice.ps1`。需要本机安装的 TD；Icarus 已随工程保存在 `tools/iverilog`。

专项覆盖 8 首上限、分散簇 WAV、曲尾循环、NEXT/PREV/首尾、SD 在途切换、旧 FIFO 清空、坏格式后恢复、退出/重进、拔卡重挂载，以及真实串行时钟下的左右声道与有符号音效边界。原有 WAV/SD 仲裁/FIFO/HDMI 接收回归同时保留。

这是待实板验证的版本。仿真和 FPGA 内部时序不能代替跨板杜邦线的信号质量、实卡带宽、HDMI 接收设备和扬声器的验证。语音正确率 92.5% 仅来自开发期留出合成录音，尚无真人独立录音或实体板验证。

随附的 card_test/TEST001.WAV、TEST002.WAV、TEST003.WAV 是 220/660/1320 Hz 的原创短测试音，可复制到 FAT32 卡根目录辨别上下切歌与音效。

ACA 仍有 11161 LUT、15 块 BRAM9K、20 个 DSP 可用；15 块 BRAM 的原始容量约17 KiB。2026-10-20 核对数据手册补充：EG4S20BG256 另外还有独立的 8 MiB 内嵌 SDRAM，不能用剩余 BRAM 容量代表所有可用图像存储。当前 ACA 工程尚未接入 SDRAM 和显示链路，现有图片缩放继续使用 HX 的图像流水线和帧存储。当前未加入倍速；保留音高的变速需要另外设计算法和缓存。漫画扩展分析见 [分区交互漫画方案评估](docs/交互漫画方案评估.md)。

打包复现：`./voice/run_voice.ps1 -Build` 会先运行语音整数对照、全部回归、两板完整实现和ROM审计，再调用 `tools/package_music_release.py` 生成最终 deliverable。若仅重建硬件，可使用 `./run_all.ps1 -Build`，生成各板标准 deliverable，之后完成审计再打包。

图片观感缩放已接入HX：短按K4切到操作页3，K1放大、K2缩小、K3恢复1倍，支持0.5/1/1.5/2倍。详见 [图片缩放说明](ZOOM_上板测试.md)。
