# 板上语音特征与拒识原因抓取

基于 `voice_robust_20261023`，保留整句归一化模型、所有音效及通信抗干扰逻辑。
新增诊断输出，模型、特征计算和命令接受条件不变。冷却期间已识别但不发命令的
情况也会产生诊断拒识提示，不改变实际命令事件。

现场反馈：新版仍然 HEAR→AGAIN。2026-10-23 供电后 COM3（CH9102）可访问，
4秒读到674字节，校验出42个旧协议诊断包。旧包能证明编解码器无报错、PCM计数
持续更新，但不含KWS特征、端点和模型分数，不能据此判断具体拒识原因。

本版只需更新ACA：`aca420_voice_capture.bit`。HX继续使用语音反馈版，屏幕文字
保持原样，避免再刷HX；识别结果通过已通的USB串口直接读取。
下载后进入 VOICE READY，保持USB串口连接。请告诉助手“已刷好”，由助手开始
20秒抓取，再按提示自然说指定口令，便于把已知标签与板载特征对应。
不能用未确认标签的录音直接训练。

## 数据与判定

每32ms输出16维实际送入识别器的特征、端点编号、有效语音帧数、句长、三次完整
整数推理分数和拒识位图。语音模式下取代旧诊断串口，115200 8N1，不影响跨板UART。
非语音模式仍输出原A5 5A 01诊断包。

拒识位图：bit0有效语音不足6帧；bit1整句含句尾超过96帧；bit2开口前未满足
8帧安静；bit3历史窗口未就绪；bit4至少一次模型优先判为背景；bit5至少一次
分数差低于791；bit6三次方向不一致；bit7命令冷却尚未结束。多个原因可同时出现。
模型分数未生成时是零，不能把零分的argmax当成实际背景判断；应先看原因位图。

协议固定74字节，头 A5 5A 52；帧序号为16位；CRC16-CCITT初值FFFF，覆盖0..71，
72/73为低/高字节。16个特征在12..27，三组各三个有符号32位小端分数在28..63。
尾部另有PCM峰值、底噪、采样计数和发送溢出位。CRC、序号或溢出异常时，不能把
断裂特征当成完整一句话。串口抓取工具保存原始数据及解析结果，不自动训练。

手动抓取：`powershell -File tools/capture_voice.ps1 -Port COM3 -Seconds 20`。
解析：`python tools/decode_voice_capture.py verification/voice_capture_时间.bin`。
输出 `.features.npy` 与 `.json`，保存真实特征及硬件判断，方便后续复现和训练。

验证：旧数值回归逐值一致，拒识原因单独验证，完整UART接收验证最后频带对齐、
快照不被后续输入覆盖、CRC、丢帧与主机解析，双板音乐/语音握手回归及最终时序。
这是一版抓取诊断固件，尚未修复现场识别，不宣称提高真人正确率。
