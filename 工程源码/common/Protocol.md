# 双板协议 v1.2（语音试验版）

v1.2 保留包格式、CRC、握手、重试和去重，增加以下语音字段。下面原 v1.1 字段说明用于旧节奏快照的兼容读取。

- ACA 状态 byte2 bit7=1 标记语音版本；byte1 bit7=语音模式请求，bit6=已取得主板许可并正在运行。byte3 bits1:0=最近接受的口令，bits3:2=当前模型类别，0拒绝/1下一张/2上一张；它们不是统计置信度。
- 普通 STATUS/EVENT ACK：byte0仍为被确认type，byte1 bit0=主板语音许可，byte2=A5版本标记，其他位为0。正常 HELLO ACK 仍为 byte0=3，其余0；请求重握手仍为 byte0=3、byte1=1、其余0，不混用语音许可。
- ACA 只有在本地选择语音模式、链路在线且收到带A5标记的许可后才运行识别；超时/主板要求重握手时清除许可。旧主板没有新许可，不能启动新识别。
- HX 收到语音请求后停止音乐和自动播放，再通过后续 ACK 许可。语音状态有效时，事件1=下一张、2=上一张；退出语音状态后仍兼容旧事件2=暂停恢复、3=FX。新 ACA 只在语音模式发送1/2。
- 整包仍在视频帧边界提交。图片方向事件在 SD 域重新同步，在安全调度边界执行，最多保留一个等待请求。

## v1.1 基础格式与历史状态字段

两板50MHz，UART 8N1，prescale=54：实际115740.74 baud，相对115200偏差+0.469%；两板参数相同。

固定38字节：A5 5A type seq payload[32] crc_low crc_high。CRC-CCITT，poly1021，initFFFF，覆盖type/seq/32字节payload；payload低8位先发送。

| type | 含义 | payload |
|---|---|---|
| 1 | ACA状态 | 下表32字节 |
| 2 | ACA事件 | byte0=1 NEXT / 2 暂停恢复 / 3 FX；其余0 |
| 3 | ACA HELLO | 0 |
| 4 | HX ACK | byte0=被确认的type，seq回显；byte1=0 |

HX收到非HELLO而本地没有会话时返回type4，byte0=3，byte1=1，表示请求重新握手。ACA丢弃旧会话在途/排队事件并重新HELLO；这不是普通HELLO ACK。无有效会话不得执行事件。

状态payload：
- byte0 bits0演示/1学习/2codec完成/3codec失败/4噪声校准完成/5削顶/6事件发送失败或队列溢出/7DSP过载或溢出。
- byte1 bits1:0槽、4:2学习进度；byte2低3位已学习槽位。
- byte3=匹配结果100或0，是二值结果，不是统计置信度。
- byte4..11八柱高；byte12..27十六点波形，128为零。
- byte28..29瞬时幅值、30..31噪声，16bit小端。

20Hz状态，事件一个在途+一个排队；100ms重试间隔，最多5次发送（首次+4次重发），不是首次后再重发5次。相同seq事件不重复执行。1秒无有效帧离线。单主机/单从机停等设计；仅比较最后事件seq，不用于乱序网络、多设备或安全认证。seq8bit回绕在停等连接下正常。

CRC坏包不进入端点，10ms字节间超时重置解析器。ACK只确认合法会话/序号/类型；重连不重放断线期间积压事件。握手快照在视频帧边界提交。


## 音乐扩展 v1.3（2026-10-18）

EVENT payload byte0 扩展为8位：4=下一首音乐，5=上一首音乐，6=保留的音效按键通知。主机分别输出 music_valid/music_command 与旧 command_valid/command，音乐码绝不截断为两位而触发翻页或暂停。ACK、序号去重、重发和断线规则保持不变。声音效果实际选择以 STATUS byte2 bits4:3 为准（0原声、1半幅、2低通、3四倍饱和失真），因此即使通知丢失，周期状态仍可恢复选择。主机仅在非语音模式执行切歌；语音指令1/2继续为下一张/上一张。

音效数据不走 UART，单独四根数字音频线由 HX 提供 BCLK/LRCK/原始音乐，ACA 返回处理后串行数据，仍送 HDMI。
